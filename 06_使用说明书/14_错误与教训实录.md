## 一、硬件与接线安全

- **空中 RC6 急停断升力自由落体摔机（复发 4~6 次，炸机级）**  
  经过：09-30 161 号飞行在 6.8m 高度因电池低压触发 RTL 爬升中，飞手按 RC6 急停，四电机怠速自由坠落；10-07 约 3~5m 再按急停；10-08 三次自主飞（233/234/235）全部以 EStop 摔机收场（234 在 1.26m、235 在 2.51m）。根因：把急停当常规收场手法，空中急停 = 立即断电断升力；前三段贴地急停固化了危险习惯。后果：多次机体侧翻、Crash Disarming、EKF 摔机后状态失真。纠正：**急停只许地面或 <0.5m 贴地使用；空中中止走 PosHold 接管 + LAND；failsafe-RTL 触发后禁碰急停**，写入操作卡硬条款。

- **EKF3 空中切核致姿态翻转 169° 坠机（09-26，炸机级）**  
  经过：末段爬升 3.9m 时 EKF3 空中切核，姿态估计瞬间翻转 169°，撞地检测强制上锁。根因：EKF3 空中核切换（倾向性定性：双罗盘一致性差——空中 53mG——与振动削波为疑似诱因）。后果：机体摔落翻覆。纠正：重校罗盘、室内悬停零切核验证、每次飞行后查 lane switch 事件；**PID 不动**（默认 PID 悬停质量优良，根因在状态估计非控制律）。

- **RTK rover 5V/GND 反接（09-11/09-15，烧器件级）**  
  经过：按旧 6P 直通线接 RTK-01-R，rover 灯不亮、飞控四档波特率全零；后续勘误发现旧文档针序本身就是错的（旧映射 1→3/2→4/3→6/4→2/5→5/6→1 全作废），1:1 直通使 FC 5V 撞 rover 针 1 GND。根因：规格书表格串列误读，未逐列核对 P9 实表。后果：疑似烧毁 rover 串口输出（09-17 封存待售后）。纠正：**正确映射 = FC 第 k 针 → rover 第 k+1 针循环移位**；任何新线缆上电前万用表两头逐针，rover 侧唯一 ~5V 必须量在针 2。

- **云台 6S 直连必烧（09-11，烧器件级）**  
  经过：STORM32 云台输入上限 10~16.8V（4S 满电上限），整机 6S 满电 25.2V。根因：未核对供电规格。后果：直连必烧云台。纠正：加独立 12V 降压；最终 09-18 直接砍掉云台支路（减重 180g，不需要新增降压件）。

- **UBEC 出厂 DIP 档位不定有超压烧舵机风险（09-18，烧器件级）**  
  经过：Holybro UBEC 到货为 6.0/7.2/8.0/9.2V 四档，出厂默认档位未知。根因：出厂 DIP 档位不可信，丝印颜色不作数。后果：7.2V 以上超舵机规格，直连可能损坏。纠正：**上机前必须万用表实测 6.0V 档**，封标防碰；档位以表为准。

- **TELEM3 5V 接上 Jetson 40pin 形成双 5V 源回灌风险（10-04，烧器件级）**  
  经过：检测发现电池 0.00V 但 FC 仍活——FC 由 Jetson 40pin 5V 供电。根因：未按 02 册「5V 不接」口径接线。后果：接电池后 PMU 与 Jetson 双 5V 源顶牛回灌。纠正：接电池前必须撤 TELEM3 束线里的 5V 线。

- **A1/A2 舵机本体不动因插头虚插/错位（09-18，安全级）**  
  经过：飞控侧多轮 PWM 回读全绿但 A2 本体不动，用户轮 7 报「动了」实为仅 A1 动作。根因：插头虚插/错位；拨舵机臂手感二分（硬=带电保持查信号、软=无电查供电轨）。后果：十二轮台架才确认，A2 列比赛日风险件。纠正：重插即愈；后续评估更换插头线材；每次上电例行连扫两路重点盯 A2。

- **PMU 六针小线未插致电压读数 0.00V（09-09）**  
  经过：电池已接、电调鸣叫，但飞控电压显示 0.00V。根因：PMU 串在主电路上有电，但 PMU 6pin 数据/供电链路未建立。后果：误以为电源模块或参数故障。纠正：插 POWER1 后读数 22.92V 正常；**主电到位听电调鸣叫，PMU 链路看飞控电压读数**，两维度独立排查。

- **PPM 直通线针序镜像致接收机反接掉电（09-08/09-09）**  
  经过：FS-iA6B 按 SBUS 口接，RC 全零；信号线一碰飞控接收机就掉电。根因：FS-iA6B 根本没有 SBUS 输出（只有 PWM/iBUS/PPM）；且 iA6B 中间针 VCC、飞控中间针信号，直通 = 电源反接。纠正：改用 PPM 按对角线映射；**线壳侧看针位会左右镜像，必须万用表实测**。

- **电调 OPTO 无 BEC 且飞控不供电，全系统无 5V 源（09-09/09-14）**  
  经过：舵机指令全 success 但本体不动，排查发现全系统无 5V 源。根因：好盈 XRotor 40A 是 OPTO 无 BEC、飞控不为舵机供电（A1~A8 正负悬空母线）。后果：舵机等于没插电。纠正：台架用手机充电头剪 USB 线注入 5V（或 4AA 电池盒）；装机用 UBEC 注 A 排母线。

- **6S 满电 25.2V 不可直连 Orin（09-09）**  
  经过：Orin DC 口上限 19V，6S 满电 25.2V 不可直连。纠正：用 6S→12V/5A 降压模块，接前万用表调准电压并定中心正极性。

- **XT60 本体 60A 为全系统电流瓶颈（09-09）**  
  经过：采购 XT60 一分三时确认主路 12AWG 支路 18~20AWG。纠正：线长每根不超 15cm，选型留余量。

- **舵机插件错插 CH8 致空投减半隐患（10-04）**  
  经过：逐通道点动实锤一只释放爪插在 CH8（MAIN8/I/O 侧）而非 SERVO9/10。根因：插接错口未逐通道验证。后果：若上场比赛，任务点火 DO_SET_SERVO 9/10 将一瓶投放一瓶挂机，空投减半+载重失衡砸着陆。纠正：重插回 9/10 后逐通道点动+慢速隔离复测，纳入 L2c 标准科目。

- **CAN 插头虚接致 GPS 断电后失联（09-25）**  
  经过：飞控断电后 GPS 报 NO GPS，SLCAN 嗅探 0 帧总线静默。根因：CAN 4P 插头虚接。纠正：断电重插压实+胶带应力释放；与 TELEM2 同款第二例，NEO3 为第三例——**判硬件死前先重插+重启复测**。

- **USB 经拓展坞双主机 5V/VBUS 抢夺疑似损伤飞控 USB（09-25，安全级）**  
  经过：飞控 USB 经拓展坞同时接电脑和 Jetson，之后 ttyACM 不枚举、lsusb 时有时无，两 USB 口换线均不枚举。根因：一设备一主机铁律被破坏。后果：飞控 USB 线路疑似硬件损伤，后续多次不枚举。纠正：**任何 USB 设备只接一个主机**；拔电脑线让飞控 USB 直插 Jetson。

- **蓝色标识牌被当蓝垫、牌边地面被当筒（10-01/10-02）**  
  经过：白筒检测 SAM 提示框过大把半张垫子算进去。纠正：SAM 掩码取含检测中心的连通域+面积护栏 ≤3.2×口沿长轴²；蓝垫封闭性泛洪判据替代环带蓝色占比。

## 二、飞控与参数

- **参数存储残表整族回退出厂值（10-03 至今，安全级）**  
  经过：10-03 首次发现 328 项参数从参数表彻底消失（FRAME_CLASS/MOT/ATC/WP 等），随后每次上电随机烂不同族（BATT 全组回出厂、GPS1_TYPE 9→1、RC6_OPTION 31 丢失、FS_THR_ENABLE 回 1 空中 Disarm）。根因：4.7.1-beta 参数持久化不可信，存储残留旧副本随机复活（双 bank/脏拷贝模型），证据为 GPS_AUTO_CONFIG/GPS_INJECT_TO 回退到 10-02 旧值而非出厂值，以及 STAT_BOOTCNT 136→109 回退。纠正：**每次上电先 verify_params --diff 对账再动电机**（临时家规）；FORMAT_VERSION 写 0+载体重启可重建存储但只能清场不能治病；4.6.3 稳定件作为刷机备选；定点修补时区分合法新校准与真漂移。

- **RC_SPEED=490 超好盈规格致电调长鸣（09-09/10-03，安全级）**  
  经过：10-03 插电池后电调持续长鸣，点名读参发现 RC_SPEED=490、基线应为 200。根因：490Hz 超出好盈 XRotor 40A 的 50~450Hz 规格；参数漂移回退。纠正：写一验一修回 200Hz；09-09 首次发现后应作为关键点名参数。

- **误为 ELRS 写 SERIAL6_PROTOCOL=23 污染配置（09-08）**  
  经过：按 CRSF 思路写 SERIAL6_PROTOCOL=23/BAUD=420。根因：未先确认接收机协议——FS-iA6B 根本无 SBUS。纠正：改回 SERIAL6_PROTOCOL=-1，接收机走 PPM。

- **ATC_ANGLE_MAX 单位改度，3500 触发 PreArm 超范围（09-08/09-09）**  
  经过：参数文件沿用 3500，真机报 "must be >= 10 and <= 80"。根因：4.7-beta 单位改为度，3500 按厘度写的。纠正：真机改 35，同轮复查角度速度类单位。

- **6S 机沿用 3S 低电阈值使保护失效（09-09）**  
  经过：低电严重阈值原为 10.5V 等 3S 值，BATT_CAPACITY 也沿用 3300。根因：默认值未按实机电池换算。纠正：三级阈值改 21.6/21.0/22.5V，容量 8000mAh；BATT_ARM_VOLT 首版 24.5V 过高致落地难复飞，改 22.5V。

- **GUID_OPTIONS bit0 未开致全天 Guided mode not armable（10-05，安全级）**  
  经过：10-05 全天 GUIDED 内遥控解锁被拒，用户 16↔4 反复横跳找解锁时机。根因：本 beta GUID_OPTIONS=1 默认关闭 Allow Arming from Transmitter。纠正：设 GUID_OPTIONS=1 后三连解锁验证通过；网传 bit4=无 GPS 解锁在本固件不成立——**以 MP 位编辑器截图为准**。

- **NAV_TAKEOFF param7 按海拔发送致 FC 静默拒飞（10-05/10-06，安全级）**  
  经过：任务节点把离地 3m 直接作为海拔发给 FC，场地海拔 9m/326m 下目标变成向下起飞被静默拒。根因：MAVLink NAV_TAKEOFF param7 语义是海拔（MSL），SITL 家海拔 0 掩盖了这个 bug（30/30 回归全绿盲区）。纠正：改发地面海拔+爬升高度；后续 10-07 进一步确认 Copter-4.7.1 GUIDED 起飞 param7 语义为**相对当前高度爬升量**，改发 z=2.0 AGL。

- **DISARM_DELAY=10 致解锁后十秒自动撤武装（10-05，安全级）**  
  经过：解锁成功进 TAKEOFF 后 10 秒掉武装（17:08:18→17:08:28）。根因：DISARM_DELAY=10（默认 0），FC 落地判定触发。纠正：改 0 并重启复核。

- **ARMING_CHECK 改名 ARMING_SKIPCHK 且语义相反（10-03/10-05）**  
  经过：按标准名 ARMING_CHECK 读参失败，实际 beta 实名是 ARMING_SKIPCHK=1280；且 4.6 起该参数是「要跳过哪些检查」的掩码，与旧 ARMING_CHECK 语义相反。纠正：读参用实名；**位掩码语义不能复制旧数值**，1280=跳过 BATTERY 和 LOGGING。

- **GPS1_TYPE=5(NMEA) 为 SIH 台架残留致 NEO3 无定位（09-17）**  
  经过：实机 GPS1_TYPE=5，NEO3 为 UBX 驱动，互聋；10Hz 报文但 fix_type=0 星=0。根因：SIH 台架参数未恢复。纠正：写回 1(AUTO) 秒级恢复 29 星；**fix_type=0 是没通信，1 才是搜星中**。

- **FRAME_CLASS 残表漂成 4=OctaQuad（10-03）**  
  经过：实读 FRAME_CLASS=4 而基线 1，机架成 X8 而非 Quad。根因：残表漂移。纠正：修回 1 并查 SERVO5~8 干净。

- **BRD_SAFETY_DEFLT=1 上电安全闸重开（10-03）**  
  经过：实读 1 而基线 0，安全开关插着没按则 M1~M4 无脉冲输出。纠正：修回 0 并终判验收。

- **WP_SPD 回退 10m/s 超场地物理封顶（10-04）**  
  经过：出厂 10m/s，SSOT 算本场地封顶约 8m/s。纠正：修回 4m/s。

- **PLND_ENABLED=0 致精准降落链断（10-04）**  
  经过：参数漂移回退关闭精准降落。纠正：修回 PLND_ENABLED=1 且 TYPE=1。

- **RNGFND1 定高参数被关闭与 09-24 定案不一致（09-28/09-30）**  
  经过：读参发现 RNGFND1_TYPE 10→0、EK3_RNG_USE_HGT 4→0，子参数懒加载回收。根因：疑摔机后台架临时关闭未恢复。纠正：两遍导入恢复 TYPE=10+EK3_RNG_USE_HGT=4；**懒加载参数组：写回父参数→重启→再补子参数→重启**。

- **MOT_SPIN_MIN=0.03 孤儿参数致解锁被拒（09-12）**  
  经过：打杆解锁失败，拒绝原文 Motors: MOT_SPIN_ARM 大于 MOT_SPIN_MIN。根因：飞控上的孤儿参数 0.03 低于怠速 0.13 非法，基线缺 MOT_SPIN_MIN 和 MOT_SPIN_ARM 两行。纠正：写回 0.15 并回读；待回写基线。

- **校准后未重启致 Compass not calibrated 反复（09-12 等，复发 N 次）**  
  经过：校准完成后 PreArm 仍报 Compass not calibrated，或报 Accels/Gyros/Compasses inconsistent。根因：校准数据需重启才生效；且改罗盘优先级后旧校准作废需重校。纠正：**校准后必须重启飞控加载新数据**；改优先级后必须重做六面校准；重启后等传感器热身稳定再验。

- **IST8310 External 勾选颠倒风险（09-12）**  
  经过：罗盘 External 勾选颠倒会把板内受扰罗盘当主用。根因：NEO-3 外置=IST8310、V6X 板载=RM3100（09-15 勘正旧文写反）。后果：航向漂、EKF 拒定、炸机风险。纠正：RM3100 外置勾 External 作主，IST8310 板载取消 External 仅备份。

- **写参数后立即重启丢参数（09-12，复发 N 次）**  
  经过：IST8310 External 写入后立即重启，值丢失，误判固件强制回写。根因：写参数后几秒内未等存储刷写完成。纠正：**新铁律：MAVLink 写参数后等 5 秒再重启**；验收以独立回读为准不问 ACK。

- **罗盘校准 Z 轴偏移偏大（09-12）**  
  经过：RM3100 -396、IST8310 +238，经验值 <150。根因：室内钢筋和桌架磁污染。纠正：解锁一致性检查过了就用，户外重校。

- **双罗盘方向夹角 36.4° 判不一致（09-17）**  
  经过：两块罗盘磁场强度正常但方向夹角 36.4°。根因：台架磁干扰或校准时转身不充分。纠正：换室外空地重做罗盘校准，目标夹角 <10°。

- **GPS_AUTO_CONFIG=2 曾被疑漂移实为官方 CAN 口径（10-05）**  
  经过：GPS 上电配置窗口约 1~3 分钟，期间武装被阻。根因：ArduPilot GPS_AUTO_CONFIG=2 官方 CAN 口径，上电经 CAN 重配 X20P 的代价。纠正：保留不改但写入上场风险表。

- **COMPASS_PRIO3_ID 指向缺席罗盘致 Compass 3 not found（10-02）**  
  经过：PRIO3=97539 指着一颗不在位的罗盘（X20P CAN RM3100 枚举挂账项的陈旧优先级）。纠正：写 0 消除报错，原值留档。

- **LOG_DISARMED 长开致 14 小时 1.18GB 日志（09-30/09-24）**  
  经过：158 号日志一次上电写 14 小时/1.18GB。根因：外场未关闭 LOG_DISARMED。纠正：外场/比赛日改 0，回拉后轮转清卡。

- **RTL_ALT_M=15m 放大室内摔机风险（09-30）**  
  经过：摔机段从 1.4m 爬至 6.8m 被打断。纠正：建议降到 5~8m。

- **BATT_LOW_VOLT=21.6V 偏低致带载提前塌压（09-30）**

## 三、通信链路与 MAVLink/ROS

- **rclpy 回调内调 shutdown 死锁（09-06/09-07）**  
  经过：check_vision_contract 定时器回调内调用 rclpy.shutdown()，spin 卡死，SIGTERM 都杀不动。根因：回调内 shutdown 破坏执行器。纠正：改 Future + spin_until_future_complete 标准范式；或抛自定义异常干净退出 spin。

- **ArduPilot 未见 GCS 心跳不主动流送（09-07/09-10）**  
  经过：mavros 连上但 LOCAL_POSITION_NED 等无数据。根因：mavros 不冒充 GCS，SITL 需看到 GCS 心跳才流送。纠正：mavros 开 gcs_url 桥 + pymavlink 心跳泵（必须**先发后收**）。

- **SR0_* 参数在 4.7-beta 被废除（09-10/09-11）**  
  经过：按 SR0_* 配置消息流，param 读回 None，SR0 文件被静默忽略。纠正：改用 mavros set_message_interval 服务逐条订阅 7 条消息 @10Hz。

- **裸 SITL 只发心跳其余零流（09-11）**  
  经过：裸 SITL 实测只发心跳，位置等消息零流。纠正：加 REQUEST_DATA_STREAM ALL @10Hz。

- **mavros 参数同步前返回陈旧值（09-09）**  
  经过：读回原值 0 设置后读出 5 自相矛盾。根因：mavros 起动 4 秒就读参数列表同步约 10 秒。纠正：先等 mavros.log 出现 "parameters list received" 再操作 set。

- **mavros 2.14 接口改名 ParamSetV2 且无 param/get（09-09）**  
  经过：param_set 一直等不到服务。纠正：用 /mavros/param/set（ParamSetV2），读参数用 get_parameters。

- **ros2 topic echo --once 探连接不可信（09-09 首证，复发 4+ 次）**  
  经过：--once 依赖单次消息+daemon 图缓存不刷新，在 DDS 发现慢或 daemon 僵死时 30s~60s 全 miss，链路其实秒连。后果：多次误判链路未通/已通，10-04 甚至发生在仓库闸门脚本自身。纠正：**链路判据一律不碰 DDS**——用 pymavlink 直探心跳，或任务节点日志状态迁移，或流式订阅。

- **多网卡致 DDS 发现失败节点互不可见（09-07/10-09）**  
  经过：WiFi+RNDIS/多网卡时组播跑错网口，节点互相发现不了。根因：FastDDS 默认组播选错接口。纠正：ROS_LOCALHOST_ONLY=1 或 UDP-only profile；10-09 确认 DDS 图分裂根因=进程环境不一致，统一 source+ROS_LOCALHOST_ONLY=1 解决。

- **mavros 消息类型大小写写错致发送失败（09-25）**  
  经过：三条 STATUSTEXT pub 全报失败，把消息类型写成 Statustext。纠正：查实际消息类型后改用 StatusText。

- **ArduPilot 跨口转发只对机载电脑身份生效（09-27）**  
  经过：飞控只转发 sysid1/compid240（机载电脑）身份的 STATUSTEXT；GCS 身份发的被丢弃；USB 口不外转。纠正：判读行走机载电脑身份（设计要求正好合规）。

- **mavros 2.x 无 set_parameter 服务（10-09/10-10）**  
  经过：vgps 等待不存在的服务名 set_parameter 60s 报服务不可见。纠正：写参数服务实为 /mavros/param/set；或经串口桥原生 MAVLink PARAM_SET 直写。

- **MAVLink 243 非重启指令（09-25/09-26，复发 2 次）**  
  经过：243 被误当重启指令，实际是 PREFLIGHT_STORAGE，ACK=UNSUPPORTED；正确重启是 245。根因：命令枚举误用。后果：09-25 ETH 节「243 重启」实际从未重启，参数持久化验证失真。纠正：用 245，并以心跳 6 秒空洞确认重启。

- **recon 拍照确认 0/6 因 m3 脚本从未拉起回执节点（10-09）**  
  经过：m3 栈从未拉起拍照回执节点，run6 的 6/6 靠 09-12 遗留自启 hazard_recon 僵尸进程碰运气回 ack。根因：栈缺拍照回执替身。纠正：m3 脚本补 fake_recon_node 握手替身，capture_request→capture_done 0.1s 专用握手。

- **GPS2 流订阅漏 mid24 致 mavros 恒 NO_FIX（10-08）**  
  经过：10-08 GNSS 判读体系让任务首次依赖 NavSatFix.status 过门禁，SITL SERIAL0 该流从未被请求。纠正：m3/m2/mission/regression 四脚本流订阅清单补 mid 24。

- **裸串口探针并发开 ttyTHS1 致 mavros 崩溃（09-27）**  
  经过：一边 mavros 跑着一边裸开 ttyTHS1 发探针，mavros serial EOF 崩溃。根因：mavros 独占串口，并发裸开触发 EOF。纠正：**裸串口探针前必停 mavros**。

- **pymavlink param_set_send 签名版本坑致空跑（09-25/10-05）**  
  经过：调用 param_set_send 传 target 前缀参数报 TypeError，参数根本没写进去。根因：pymavlink 版本 API 差异。纠正：**写入后独立回读校验**，不问 ACK。

- **回执假阴性误报写入失败（09-25/09-28/10-03）**  
  经过：USB 链路 PARAM_SET 回执全丢，load_params 两遍全报「写入未确认 0/4」，但独立回读证全生效。根因：4.7-beta compid=0 链路收不到 PARAM_VALUE。纠正：验收以 verify_params --diff 实读为准，勿盲重试。

## 四、机载软件与算法

- **aim_point 两项符号全反导致落点偏 10.4cm（09-30，高危）**  
  经过：drop_logic 的 aim_point() offset 项和弹道前移项全写成加号，物理应为减号。根因：被 payload_offset=[0,0] + 近悬停释放掩盖近月；单测按错误实现写。后果：实测下落点偏 10.4cm，15cm 筒必丢。纠正：C++ 与 Python 双端同步改为减号，更新双测期望值，SSOT 补方向说明。

- **测高链漏相机下沉量（09-28/09-29）**  
  经过：h_m=odom_z−ground_z−plane_z 未含光心 z 偏置，实测 A3=47.286mm 下沉在 1.3m 测高是 3.6% 尺度误差。纠正：h_m 加光心 z 偏置；直径读数由 0.260 回到 0.2505m。

- **起飞链两处 GNSS 载体判据缺陷使 0.9× 判据永不达标（10-07 至 10-08，高危）**  
  经过：地面 GNSS 垂直漂移 ±5m，起飞完成判据和「已在空中」守卫都用 GNSS 相对高，导致地面误触拒飞或 0.9× 永远够不着。纠正：起飞守门改 odom 差；0.9× 判据增 odom 或分支；TAKEOFF 态放宽 odom 门禁让 FC 自飞。

- **odom 断流 1s 即 fail_and_return 误杀自飞（10-07）**  
  经过：到 2m 后 1 秒内发 LAND，观测到 209 两次自主飞到顶即自降。根因：flight_gate_ok 判 Odometry stale 后直接进 LAND。纠正：TAKEOFF 态改 flight_gate_ok(false)；odom 门禁在 SEARCH 等流式态保持满门禁。

- **DO_SET_SERVO 被拒仍推进载荷计数（09-20）**  
  经过：mission_node 在 FCU 拒绝舵机指令时只 WARN，sequencer 照常 ++payloads_released_。后果：真投虚报投放数。纠正：DropSequencer 加 abort_fire/hold_elapsed，拒绝回退并连击 3 次 fail_and_return。

- **send_servo 不检查未决 future 覆盖旧请求（09-20）**  
  经过：新指令发出时未判上一条结果是否已回。纠正：加 command_future_.valid() 守卫。

- **视觉排名抖动导致锁定目标跳变（09-07）**  
  经过：检测排名不稳定。纠正：排名签名连续 0.8s 不变才允许锁定。

- **冻结坐标盲投导致投放门控失效（09-07）**  
  经过：目标坐标冻结后仍按旧坐标投放。纠正：门控内建 target_age≤0.5s + 一次重捕获 + 弃桶；两瓶投一点暴露两筒独立性缺失，强制合并两瓶独立性。

- **外推三坑：冷启动死锁/EMA 与类速打架/浮点噪声赢过票数（09-27）**  
  经过：累积器速度需连续关联才建立但碎票永远建立不成；EMA 收敛慢与类速冲突致 4/2 震荡分票；浮点 1e-16 差异压过票数裁决。纠正：改类级速度、弃 EMA、打平判 1e-9 容差。

- **Stab 前飞掉高误判为任务故障（10-07）**  
  经过：203 号日志 28 分钟全是 Stabilize 手动飞行，前推俯仰自然掉高。根因：未先确认飞行模式。纠正：看 dataflash MODE，手动练习用 PosHold。

- **高度基准冻结时刻选择反复（10-08）**  
  经过：先定上电 LOCK_FRAME 冻结，飞手等待期 GNSS 漂移 ±5m 全落判据；后改解锁上升沿重冻。纠正：**任务相对高度=实际−解锁时基准**，同源同刻抵消漂移；LOCK_FRAME 撤销 GNSS 冻结。

- **LOCK_FRAME 缺静止判据会边滑边锁（10-09）**  
  经过：只有航向判据，机体被推动会锁出整体平移。纠正：增水平速度≤0.15m/s 持续同窗静止判据。

- **释放门控缺角速度判据致振荡盲区（10-09）**  
  经过：八门控倾角瞬时过零的振荡是盲区。纠正：九门控增角速度≤5°/s。

- **PILOT_OVERRIDE 后仍可能重发指令与飞手抢权（10-08/10-09）**  
  经过：override 后回仓重试仍可能发 DO_SET_SERVO。纠正：tick 顶部 stow 重试加状态门闸，只回收在途结果不重发。

## 七、操作流程与外场

- **排障先做 PreArm 只读诊断而非硬试解锁（10-05）**  
  经过：解锁被拒后从 PreArm 报错逐项修，快速定位唯一拦路项。纠正：用 MAV_CMD_RUN_PREARM_CHECKS(24194) 触发并收听 25 秒（该工艺首证于 09-17/09-25，10-05 为实战应用）；放电推杆前油门最低、SWA 急停低位、遥控器开机。

- **60 秒窗口零校准，校准全前置（09-24）**  
  经过：用户问每次上电都校准来不及。纠正：加速度计/罗盘/遥控校准全是一次性存参，上场窗口只做自检+安全开关。

- **一个 USB 设备只接一个主机（09-25）**  
  经过：飞控 USB 经拓展坞同时接电脑和 Jetson，两主机抢设备导致 COM 口时隐时现。纠正：拔电脑线，飞控 USB 直插 Jetson；拓展坞不能是总线供电的。

- **接电池瞬间串口抖断需容错重连（09-09）**  
  经过：脚本读到一半串口断开。根因：接电池时飞控重启或 USB 抖动。纠正：对 SerialException 容错重连。

- **飞控 USB 间歇未枚举致 COM 口漂移（09-14 等，复发 N 次）**  
  经过：COM5 消失或变成无名 USB 串口设备。纠正：连不上先扫端口/Get-PnpDevice -Class Ports，不判变砖；换线换口 A/B 测试红线。

- **Mission Planner/地面站占 COM 口致脚本连不上（09-05 等，复发 N 次）**  
  经过：脚本连飞控时 COM5/COM17 被 Mission Planner 占。根因：串口独占，工具未自动提示。纠正：跑脚本前先杀 MissionPlanner.exe 或断连接。

- **pkill -f 自匹配反复杀掉自己（09-06 首犯，复发 10+ 次）**  
  经过：pkill -f mavros_node 等模式匹配到自身命令行，把 ssh 会话或脚本自己杀了。根因：pkill -f 全命令行匹配，命令文本里含目标串。纠正：**用 [x] 方括号防自匹配**（mavros_[n]ode）；或按 PID 直杀；kill 与 start 拆成两条 ssh。

- **timeout 只杀直接子进程致孤儿（09-06）**  
  经过：timeout 结束只杀直接子进程，ros2 run 拉起的孙进程变孤儿占住管道。纠正：长跑工具文件重定向 + pkill -9 兜底收尾。

- **batch 后台任务抢端口造幽灵死亡（09-10）**  
  经过：多个后台任务重叠 reset 互相杀抢端口。纠正：**严格串行单线程操作**。

- **SSH 会话取消不杀远端 onekey 链（10-05）**  
  经过：用户本地 Ctrl-C 后远端进程继续跑 267s。根因：ssh 会话死活不绑定远端进程组。纠正：中断跑须上机 pgrep 复核；远端 setsid+落日志文件后轮询。

- **非交互 ssh 不读 .bashrc 需内联 source（09-16/10-01）**  
  经过：远程 ssh 直接起节点报 Rclpy 缺失。纠正：命令内显式 source /opt/ros/humble/setup.bash + FASTRTPS profile。

- **stamp 用 ROS 墙钟 vs odom 用 FCU 时间基准致全拒帧（09-12）**  
  经过：真值感知用墙钟打戳，P0.4 插值全部拒帧。纠正：感知消息戳取帧时刻，odom 样本取最新 odom header.stamp 同源。

## 八、工程管理与文档

- **gitignore 行内注释致 17GB 被误加暂存（09-06）**  
  经过：首版 .gitignore 写行内 # 注释，/* 规则失效，git add 开始吞 17GB 厂商资料。根因：gitignore 不支持行内注释。纠正：注释独立行；改 .gitignore 后必须 git status --short 核对再提交。

- **仓库 .git 膨胀至 12GB 待 filter-repo 瘦身（09-09）**  
  经过：历史大文件曾入库。纠正：待拍板 filter-repo。

- **二进制产物混入暂存区（09-12/09-13）**  
  经过：build_test 5.7MB exe/pdb 与 test_*.exe 已进暂存。纠正：入库前清构建产物、复查 >500KB 文件、权重数据集白名单留库外。

- **并行会话写日志冲突致 09-26 日志 0 字节（09-26）**  
  经过：并行 Re0 会话提交 56e8248 时「按目录锚点+文末节重建」把总编工作区文件清成 0 字节。根因：多会话并行改同一文件，重建式落库对未提交内容是数据风险。纠正：恢复优先级=会话上下文重建＞git show 提交版＞fsck 悬空 blob；日志按「追加续写、不覆盖历史」原则。

- **CRLF 污染 Linux 脚本（09-06 首犯，复发 5+ 次）**  
  经过：Windows 写文件带 CRLF，Jetson 上 bash 报 \r 错误。根因：跨平台换行符差异。纠正：仓库 .gitattributes 设全仓 LF；转 LF 并 bash -n 验证；推脚本前后必查行尾。

- **11 册字面 CR 被文本模式拆成 LF 假 diff（09-30）**  
  经过：python 文本模式整文件读写把 7 个语义性字面 CR 拆成 LF 并 CRLF 回写，705 行假 diff。根因：universal newlines 破坏字面 CR。纠正：从 HEAD blob 二进制重组只叠加真实新增；**含字面 CR 文件禁用文本模式整文件读写**（AGENTS.md 第 7 条）。

- **多层转义把字面反斜杠 r 解读成真 CR 字节（09-30）**  
  经过：工具调用 JSON→heredoc→Python 三层转义把行内 \r 变成真 CR 字节，新行碎 3 行+新增 5 个裸 CR。纠正：回滚后用 raw string 重做并加裸 CR 计数断言。

- **AI 幻觉编造 git 输出与文件内容（09-30）**  
  经过：多轮工具输出不存在的章节、锚点、路径和修复记录，AI 主动认错并停下。根因：长时间连续工具调用进入幻觉状态。纠正：停下认错，让用户跑 git status 验证，清醒后分块暂存提交。详见第九章。

- **SSOT 文档地图缺登约九处新文档（09-17）**  
  经过：新文档产出后索引未同步，地图缺登、目录 README 台账落后。重新发现孤儿资产 RTK-01-R 针脚图全库零引用。纠正：SSOT 文档地图 33 项目标逐行存在性验证；每个新增文档登记地图与索引。

- **定案翻案后文档边角旧口径残留（09-25 等，复发 N 次）**  
  经过：只改主结论行，排障表/台账/名词表/检查表等边角保留旧口径，审计发现 19 处残留。根因：缺少全仓扫尾机制。纠正：每次定案/翻案后全仓 grep 旧口径扫描+抽检清零。

- **教程源码事实与现行代码系统性失效（09-26）**  
  经过：Re0 教程 v11 八门控、PWM、目录结构等与现行三包代码不一致。纠正：引用教程前必须过勘误表；数值以 SSOT/日志为准。

- **工作日志按日散落或相对时间「昨天拍的」（09-12/09-17）**  
  经过：日志出现相对时间词、日期笔误、小节插入错位。纠正：绝对日期；单文档总编制；追加剧只追加不覆盖。

## 九、AI 协作中的错误

- **AI 幻觉状态编造章节/锚点/路径/修复记录（09-30）**  
  经过：长时间连续工具调用后 AI 进入幻觉状态，多轮输出不存在的文件内容、假设的修复记录和错误的 git 状态，自己意识到后主动停下认错。根因：连续多次工具调用不可信输出叠加，未及时收敛。后果：若在幻觉下 git add/commit 有危险。纠正：停下认错，让用户跑 git status 验证，清醒后分块暂存提交；此后在不可信输出环境下停用 heredoc，改用 Write 落成真实文件再执行。

- **AI 凭记忆给错 QuadX 方向表致用户白换相线（09-08）**  
  经过：AI 给用户「右前/右后顺时针」的方向表并要求对调相线，实际凭记忆写反两组。根因：未查源码 AP_MotorsMatrix，把方向因子(YAW_FACTOR_CW/CCW)语义理解反。后果：用户白换相线又换回，调试反复。纠正：查源码混控无变号和 NED 符号约定重推；以源码矩阵+物理推导+官方 wiki 三重交叉验证定表并公开道歉。

- **AI 多层转义损坏文件（09-30）**  
  经过：工具调用 JSON→heredoc→Python 三层转义把行内反斜杠 r 解读成真 CR 字节，新行碎 3 行。根因：未用 raw string 且未做字节断言。纠正：回滚后用 raw string 重做并加裸 CR 计数断言拦截。

  定案：原计划 v1 合成预训练+实拍微调；实际发现 COCO 直训 mAP50=0.963 基本达标且省一整个训练阶段。  
  动因：已验证路线优于计划旧链。  
  最终定案：COCO 直训定案为新路线，废弃 v1 合成链；逐类 mAP50≥0.90 无豁免。

- **高度基准：上电冻结→全切 GNSS→解锁沿重冻→暂缓（10-08）**  
  定案：10-08 先定上电 LOCK_FRAME 冻结 ground_amsl；同日又拍板 EK3_SRC1_POSZ 全切 GNSS；后检 hgd S50 称不能仅因更准把低空高度观测改成 GNSS 源；最终解锁沿重冻 GNSS 基准+POSZ 维持气压计主+激光辅助。  
  动因：需连变+外部实战经验否证。  
  最终定案：POSZ 维持 1 暂缓导入；0.9× 判据增 odom 或分支免疫 GNSS 垂直噪声。

- **Windows 编译路线：Docker/WSL 一夜撞坑→Jetson 原生编译（09-15）**  
  定案：先计划在 Windows 上用 Docker/WSL 编译 ArduPilot SIH 固件；ghcr 无公开镜像、加速源 403、wsl 元数据 502 全不可达；一夜无产出推翻重来。  
  最终定案：Jetson 原生 Ubuntu 编译链（apt 装交叉编译器，xpack 10.3.1 aarch64 免 root）。

- **相机查看通路：Windows 浏览器查看器→Jetson 屏（09-22）**  
  定案：先实现 stream_view.py MJPEG HTTP 8000 端口查看，Jetson 烟测通过；后用户说「不要这个，我就在 Jetson 上看」。  
  最终定案：撤下 stream_view.py（Jetson 文件已删、仓库不留档），看画面固定 Jetson 机身屏 camera_view/detect_view。

- **鱼骨之剑：搜索形态 蛇形→悬停优先+蛇形兜底（10-08）**  
  定案：蛇形覆盖 6 带无盲区，但单点悬停覆盖仅 2.6~4.7m 盖不住 2~5m 桶距；覆盖数学否决纯悬停。  
  最终定案：找桶段采用悬停优先，12s 窗口未锁定则回蛇形首航点兜底。

- **数传 433→915 主力（09-23）**  
  定案：433 X6 非标准 SiK 固件，AT 指令集不兼容，进不了配置模式；915 端到端双向验收通过。  
  最终定案：915 主力、433 转备件；数传半通先重对频再动线。

- **目标模型：统一 det v4 → 独立小模型（10-12）**  
  定案：14 类统一 det 模型 v4 因机载相机域泛化失败白蓝底全瞎；已拍板不切换。  
  最终定案：生产维持 v2 独立小模型（recon/bucket/hcircle 三槽位分离）。
