## 1. 地面站层（跑在你的 Windows 电脑上）

### 1.1 Mission Planner（地面站软件）

- **是什么**：Windows 免费软件，人看飞机、指挥飞机的主窗口：地图、姿态、电池实时显示；刷固件、改参数、校准、测电机都在这里点。
- **本项目怎么用**：V6X 用 USB 线或数传连电脑，MP 连上后做 03 册全套操作（刷 `.apj` 固件、参数导入两遍、加速度计/罗盘校准、电机测试、日志回拉）。
- **动手 1（Windows，无需硬件，10 分钟）**：
  1. 官网 `firmware.ardupilot.org` 下载 Mission Planner，一路下一步装完；
  2. 认识四个页签：飞行数据（地图+姿态仪表）、飞行计划（航点规划）、配置/调试（参数全表）、帮助（固件安装在这里）；
  3. 左上角"连接"按钮先别点——没有飞控时点了报错属正常。
- **动手 2（需硬件：飞控+USB 线）**：插 V6X → 右上角选出现的 COM 口、波特率 115200 → 点连接 → 左下角开始滚动心跳数据包，飞行数据页的姿态仪跟着手转飞机动。第一次连上就是地面站层通关。
- ⚠️ **连飞控前先断开 MP**：命令行脚本（§1.2）要用同一个 COM 口，MP 开着会占口。这是全项目家规（AGENTS.md 红线 6）。
- **深入**：03 册全套。

### 1.2 pymavlink（Python 版飞控对话库）

- **是什么**：让 Python 程序直接说 MAVLink 的库。MP 是图形界面，pymavlink 是脚本——要自动化批量操作飞控时用它。
- **本项目怎么用**：`02_飞控与硬件/调试工具/` 的全部脚本（check_fc / motor_test / servo_test / fc_log_pull / verify_params…）和 Jetson 上的心跳泵都是它写的。
- **动手（Windows，先做完 §2.1 让 SITL 跑起来）**：

  ```powershell
  pip config set global.index-url https://pypi.tuna.tsinghua.edu.cn/simple
  pip install pymavlink
  ```

  存一个 `heartbeat.py`：

  ```python
  from pymavlink import mavutil
  m = mavutil.mavlink_connection('tcp:127.0.0.1:5760')  # SITL；MAVROS 已占用 5760 时改 5762
  m.wait_heartbeat()
  print("心跳来自: 系统", m.target_system, "组件", m.target_component)
  ```

  ```powershell
  python heartbeat.py     # 输出：心跳来自: 系统 1 组件 1
  ```

- ⚠️ 连**真机**时同一串口只允许一个客户端：MP 和脚本开一个关一个。
- **深入**：`02_飞控与硬件/调试工具/README.md`。

## 2. 飞控层

### 2.1 ArduPilot（飞控固件）

- **是什么**：烧在飞控板里运行的开源飞控软件，负责姿态内环、位置控制、失效保护、精准降落。主流开源飞控两家里的一家（另一家 PX4，本项目 09-01 后整体切到 ArduPilot）。本项目版本钉死：Copter **4.7-beta**（git dbe79216，CUAV V6X **v2** 专用固件）。
- **本项目怎么用**：烧在 CUAV Pixhawk V6X v2 上。注意：你写的任务代码**不进**飞控——飞控只管"飞"，任务逻辑全部在机载电脑（§3）。
- **动手（Ubuntu，无需飞机——把固件编译成 Linux 程序跑，这就是 SITL）**（01 册 §8 全套，摘录）：

  ```bash
  cd ~
  git clone --recurse-submodules https://github.com/ArduPilot/ardupilot.git
  cd ardupilot && git checkout Copter-4.5
  Tools/environment_install/install-prereqs-ubuntu.sh -y
  . ~/.profile
  ./waf configure && ./waf build --target bin/arducopter    # 编译，几分钟到十几分钟
  cd Tools/autotest
  python3 ./sim_vehicle.py -v ArduCopter --console --map    # 弹出 Console/Map 窗口 = 成功
  ```

  起飞四连（一行一行输，别整段粘贴）：`mode guided` → `arm throttle` → `takeoff 10`。Map 上飞机升空 = 同一份固件的"假飞控"把飞机飞起来了。

- ⚠️ 仿真里调好的姿态参数**不能**搬上真机（Iris 1.5kg vs 本机 8kg，机重差 5 倍，10 卷 §1.3）。
- **深入**：03 册 §2（真机刷固件/参数/校准）；10 卷 §3。

### 2.2 MAVLink（通信协议）

- **是什么**：飞控和外界对话的格式：一条条小消息——心跳 HEARTBEAT、姿态 ATTITUDE、位置 GLOBAL_POSITION_INT、电池 BATTERY_STATUS、参数 PARAM_SET…
- **本项目怎么用**：所有链路走它：飞控↔MP（USB/数传）、飞控↔Jetson（USB，经 MAVROS 翻译）、飞控↔Gazebo 间接。
- **动手**：§1.2 的 heartbeat.py 打出的就是第一帧 MAVLink；sim_vehicle 的 Console 每秒滚动的也是。
- ⚠️ **"连上了但没数据"的头号原因**：ArduPilot 要看到地面站心跳才开始流送遥测。MAVROS 不冒充地面站，所以必须开 `gcs_url` 桥 + 心跳泵（06 册 §3）。
- **深入**：10 卷 §4；06 册 §3。

### 3.2 Jetson Orin Nano + JetPack（机载电脑）

- **是什么**：NVIDIA 的小电脑板，带 GPU，能在机上跑神经网络。系统 JetPack = Ubuntu 22.04 + CUDA/TensorRT 一整套（本项目 L4T R36.4.7）。
- **本项目怎么用**：相机取流 → YOLO 推理 → 解算筒位 → 跑任务状态机 → 经 MAVLink 指挥飞控。**只做推理不训练**（训练太慢，去 §5.3 云端）。
- **动手（需硬件：Jetson；没有先跳过，不阻塞 §8 前三天）**：

  ```bash
  ssh jetson                              # Windows 免密远程进机载电脑（01 册 §4）
  sudo apt update
  python3 -c "import torch; print(torch.cuda.is_available())"   # True = GPU 可用
  ```

- ⚠️ 三条铁律：Jetson 直连 GitHub 不通（下载走 Windows 中转 scp/tar）；pip 走清华镜像；保持 `numpy<2`（升到 2.x 会炸系统 OpenCV）。
- **深入**：01 册 §4（SSH 免密）/§10（出厂盘点表）；06 册 §2。

### 3.3 ROS 2 Humble（机器人中间件）

- **是什么**：把一个大程序拆成多个**节点**（node），节点之间靠**话题**（topic）互发消息的通信框架。
- **本项目怎么用**：机载自研代码三个包全建在它上面——感知节点发检测结果 `/perception/drop_buckets_body` → 状态机节点消费并决策 → 经 MAVROS 指挥飞控；任务状态对外发 `/cuadc/mission_state`。
- **动手（Ubuntu，10 分钟）**：

  ```bash
  sudo apt install ros-humble-desktop          # 务必在无 conda 环境下装
  source /opt/ros/humble/setup.bash
  ros2 run demo_nodes_cpp talker               # 终端 1
  ros2 run demo_nodes_py listener              # 终端 2，收到 hello world = 通了
  ```

  日常三件：`ros2 topic list`（有哪些话题）、`ros2 topic echo /xxx`（看内容）、`ros2 node list`（有哪些节点）。
- ⚠️ 装 ROS 前先 `conda deactivate`——conda 篡改环境变量，全项目禁用 conda 装环境（01 册铁律 1）。
- **深入**：01 册 §6；10 卷 §5.2。

### 3.4 MAVROS 2.14（飞控 ↔ ROS 桥）

- **是什么**：一个 ROS 节点，把 MAVLink 翻译成 ROS 话题/服务：飞控姿态变成 `/mavros/local_position/pose` 话题，"起飞"变成一次服务调用。
- **本项目怎么用**：状态机指挥飞控的唯一通道。三条链路铁律（06 册 §3）：① `gcs_url` 桥 + 心跳泵先发后收；② 4.7-beta 无 SR0_* 参数，用 `set_message_interval` 逐条订阅 7 条消息；③ 判断连接以任务节点过 `WAIT_FCU` 为准。
- **动手（Ubuntu + SITL）**：

  ```bash
  sudo apt install ros-humble-mavros ros-humble-mavros-extras
  sudo /opt/ros/humble/lib/mavros/install_geographiclib_datasets.sh   # 必装，否则全球位置全 NaN
  # SITL 跑起来后：
  ros2 launch mavros apm.launch fcu_url:=tcp://127.0.0.1:5760
  ros2 topic echo /mavros/state       # connected: true = 通
  ```

- ⚠️ 两条实测：`ros2 topic echo --once` 会假阴性（DDS 发现慢）；MAVROS 参数列表同步约 17s，之前 set 参数静默失败。
- **深入**：06 册 §3。

### 3.5 colcon（编译工具）

- **是什么**：ROS 2 的构建工具：把工作空间里的功能包挨个编译、安装、跑测试。
- **本项目怎么用**：`~/cuadc_ws` 工作空间装三个自研包——`cuadc_mission`（C++ 状态机）、`cuadc_perception`（Python 感知）、`cuadc_interfaces`（自定义消息）。
- **动手（Ubuntu，代码来自仓库 `03_机载软件/`）**：

  ```bash
  mkdir -p ~/cuadc_ws/src && cp -r 03_机载软件/cuadc_mission ~/cuadc_ws/src/
  cd ~/cuadc_ws
  colcon build                        # 实测约 1 分 14 秒
  source install/setup.bash
  colcon test                         # 应全绿（当前口径：C++ 三件 252 checks + Python 58 例）
  ros2 launch cuadc_mission mission.launch.py
  # 无 MAVROS 时安全停在 WAIT_FCU 并可 SIGINT 干净退出 = 冒烟通过（设计行为）
  ```

- **深入**：`03_机载软件/README.md`；06 册 §2。

### 3.6 systemd（开机自启服务）

- **是什么**：Linux 的服务管理器：让程序开机自动跑、崩了自动拉起、日志进 journalctl。
- **本项目怎么用**：生产感知节点 `hazard_recon_node` 由 `cuadc-perception.service` 托管，Jetson 上电自启，比赛日不手敲命令。
- **动手（任何 Linux，拿 sshd 练手）**：

  ```bash
  systemctl status ssh                 # 看服务状态
  sudo systemctl enable --now ssh      # 开机自启 + 立即启动
  journalctl -u ssh -e                 # 看该服务日志末尾
  ```

  再打开仓库里现成的服务定义看看长什么样：`03_机载软件/systemd/cuadc-perception.service`。
- **深入**：05 册 §4。

## 5. 视觉层

### 5.1 OpenCV 4.10（传统图像处理）

- **是什么**：图像处理基础库：读图、颜色空间转换、找圆找线。
- **本项目怎么用**：三条线——白筒检测的 LAB 颜色兜底通道（神经网络不可用时分级上线）、H 圆定位（fitEllipse/Hough）、相机内参标定。
- **动手（Windows，5 分钟）**：

  ```bash
  pip install opencv-python
  ```

  存一个 `lab_test.py`（随便配一张 `test.jpg`）：

  ```python
  import cv2
  img = cv2.imread('test.jpg')
  lab = cv2.cvtColor(img, cv2.COLOR_BGR2LAB)
  mask = lab[:, :, 0] > 200          # L 通道高 = 偏白像素（白筒检测兜底通道的核心思想）
  print('偏白像素占比:', mask.mean())
  ```

  ```bash
  python lab_test.py                 # 打印一个 0~1 的比例
  ```

- **深入**：09 卷 §2（双通道检测原理）；05 册 §6（判读工程）；相机标定 `03_机载软件/scripts/calibrate_camera.py`。

### 5.2 YOLOv8 + PyTorch（检测/分割模型）

- **是什么**：YOLOv8 是单阶段视觉模型：一张图进，框/掩码/类别置信度出。PyTorch 是训练它的深度学习框架。本项目用两种形态：`-seg` 分割（找白筒+量筒口直径）、`-det` 检测（危化标识 10 类判读）。
- **本项目怎么用**：训练产出 `best.pt` 权重，机上加载推理。精度验收线 mAP50 逐类 ≥0.90，当前正式版实测 0.963。
- **动手（Windows 体验官方预训练模型，10 分钟；这不是项目模型，是体验"YOLO 是什么"）**：

  ```bash
  pip config set global.index-url https://pypi.tuna.tsinghua.edu.cn/simple
  pip install ultralytics
  yolo predict model=yolov8n.pt source=<随便一张有多人的照片.jpg>
  ```

  结果在 `runs/detect/predict/`：画好框和类别的那张图。权重自动下载慢时手动下载 yolov8n.pt 放当前目录。
- **深入**：05 册 §2~§3（数据集/训练/判读）；09 卷 §2；`01_视觉感知/数据与训练/README.md`。

### 5.3 AutoDL 云 GPU（训练）

- **是什么**：按小时租 GPU 的云平台。本项目租 RTX 4090（约 ¥2/时）跑训练。
- **本项目怎么用**：流程 = 租卡 → 上传数据集 → 一键训练脚本 → 下载 `best.pt`。数据集构建与防泄题切分规则见 05 册 §2。
- **动手**：照 `01_视觉感知/数据与训练/v2训练流水线/AutoDL租卡训练指南v2.md` 操作（租卡/上传/启动/取结果步骤仍适用；注意其中微调链已停用，现行训练路线 = COCO 预训练直训，见根 README「快速上手」）。
- **深入**：05 册 §2~§3。

### 5.4 TensorRT（机上推理引擎）

- **是什么**：NVIDIA 的推理加速器：把 `.pt` 权重转成 `.engine` 文件（FP16 半精度），在 Jetson GPU 上快数倍。
- **本项目怎么用**：上机前在 **Jetson 本机**导出 engine（一次约 10 分钟）；帧率验收线 ≥25FPS，正式权重实测 56.1FPS。
- **动手（需硬件：Jetson）**：

  ```bash
  python3 scripts/bench_trt.py       # 仓库 03_机载软件/scripts/，输出稳态 FPS
  ```

- ⚠️ engine 与"权重+设备"**双绑定**：换权重必须重导；比赛日绝不现场构建。
- **深入**：05 册 §4（部署/systemd/图像传输）。

## 6. 仿真层

### 6.1 SITL + Gazebo Harmonic（先仿真后真机）

- **是什么**：SITL = 把 ArduPilot 固件编译成 Linux 程序直接跑（"假飞控"）；Gazebo = 3D 物理仿真器，给 SITL 提供虚拟世界（重力/碰撞/相机画面）；ardupilot_gazebo 插件把两者接起来。
- **本项目怎么用**：**项目铁律：每一版任务代码先过 SITL 再上真机**（异常注入也在仿真做——冻结 SITL 进程模拟定位断流）。仿真场地 = 1:1 规则场地 `cuadc_field`，含白筒/侦察桶/危化标识/H 圆，可随机布景+自动判分。
- **动手 A（Ubuntu 22.04 台式机即可，无需任何飞机硬件）**：仓库一键脚本（03_机载软件/scripts/）：

  ```bash
  ./scripts/setup_env_ubuntu22.sh    # 一键装 ROS2/Gazebo/MAVROS/SITL/工作空间（幂等可重跑）
  ./scripts/run_sitl.sh              # gz sim → SITL → MAVROS → 任务节点一键拉起
  ./scripts/run_sitl.sh --regen      # 重新随机生成比赛场景
  ```

- **动手 B（Jetson 日常四步，07 册 §3 标准流程）**：

  ```bash
  ssh jetson
  python3 ~/sim_scripts/randomize_scene.py   # ⓪ 可选：随机布景
  bash ~/sim_scripts/reset_sim.sh            # ① 重置全栈；末行应打印 ardu=1 gz=1 p9002=1 l5760=1 c5760=0
  bash ~/sim_scripts/start_gzgui.sh          # ② 可选：挂画面（右键 iris → Follow 跟机）
  python3 ~/sim_scripts/fcu_ready.py         # ③ 就绪门禁；打印"FCU 就绪"才继续
  bash ~/sim_scripts/fc_task.sh m3           # ④ 跑任务到 DONE；预期投放 2/2 判分
  ```

- **Windows 只想看场地**：双击 `04_仿真/仿真环境/launch-cuadc-sim.bat`（pixi 版 Gazebo，只能看布景，不能飞）。
- ⚠️ 最阴的坑：环境变量 `GZ_SIM_RESOURCE_PATH` 尾部多一个空分号 → **所有模型静默加载失败**（01 册 §9.3）。
- **深入**：07 册（标准流程/模式表/排障速查）；`04_仿真/仿真环境/jetson/操作手册.md`。

## 9. 自查题

1. Mission Planner 和 pymavlink 各适合什么场合？两者同时开同一个 COM 口会怎样？（图形调试 vs 脚本自动化；抢口，开一个关一个）
2. 任务代码跑在哪里？飞控里跑的是什么？（Jetson 的 ROS 2 节点；飞控只跑 ArduPilot 固件管飞行）
3. "连上了但没数据"的第一原因？（ArduPilot 要见到 GCS 心跳才流送遥测——开 gcs_url 桥+心跳泵）
4. 为什么判断 MAVROS 连接不能用 `ros2 topic echo --once`？（DDS 发现慢会假阴性；以任务节点过 WAIT_FCU 为准）
5. 训练在哪做、推理在哪做？（AutoDL 4090 训练；Jetson TensorRT 推理；Jetson 不训练）
6. 换了权重为什么必须重新导出 engine？（engine 与"权重+设备"双绑定；比赛日绝不现场构建）
7. 每一版任务代码上真机前必须先过什么？（SITL；异常注入也在仿真里做）
8. 无任何硬件时，今天就能跑通本项目哪些东西？（仓库离线单测 58+48 例、蒙特卡洛投放仿真、SITL+Gazebo 全任务、YOLO 官方模型体验）
