## 一、调研过程与方法

分类方案不是拍脑袋定的，来自三个独立来源的三角验证：

1. **通用开源惯例检索**（Web 搜索）：开源仓库结构最佳实践、机器人/无人机比赛队伍开源案例。
2. **同赛仓库一手解剖**（本地只读分析）：`08_参考资料/外部仓库/` 里保存的 2026 CUADC 同届队伍开源仓拷贝——这是最有价值的样本，因为它们和本项目**同比赛、同任务、同技术栈**。
3. **AI 独立方案交叉验证**：让 DeepSeek-V4-Pro 在只了解项目概况与同赛做法的前提下独立给出分类方案，与本设计比对（结论：顶层分域 + 文档分层受众 + 治理文件三个核心判断完全一致，见 §2.4）。

### 1.3 同赛共性模式（决定我们方案的四个结论）

1. **「门面 README + 分域顶层目录」是共同骨架**——根 README 只做定位+战绩+导流，细节全部下沉。
2. **实机代码与仿真分离**——三家有代码的仓全部这样做（哈工大 code/sim、demo 用包边界、西安石油用 profile）。
3. **文档三档制**：越强的仓库越按受众分层（新人教程 / 开发者文档 / 过程日志），且**教训专卷是 CUADC 社区的招牌传统**（哈工大「留给后人的话」直接把经验传承做成仓库一级目录）。
4. **版本/日期快照制**普遍存在，但**强仓库都在向"最新快照工程化 + 旧版留档"收敛**。

### 1.4 DeepSeek-V4-Pro 独立方案（交叉验证）

让 DeepSeek 在只知项目概况与同赛做法的条件下独立设计，其方案要点：顶层按「硬件/软件/仿真/训练/操作」工件类型分域 + `docs/{beginner,tutorials,logs,lessons_learned}` 四档文档 + `third_party_notices`；并列出五个易犯错误（按学科模块平铺、教程日志混写、单 README 无分层、参数不锁定无法复现、忽略 LICENSE 与第三方声明）。

**与本方案的一致性**：工件类型分域 ✔、文档按受众分层且日志/教训分开 ✔、治理文件必带 ✔。
**本方案的补充**（来自一手同赛样本，DeepSeek 未见）：教训专卷应对标哈工大「留给后人的话」提升为一级板块；AI 协作契约（AGENTS.md）是西安石油验证过的新颖实践，应保留开源。

## 二、分类设计原则

综合三方调研，确定七条原则：

1. **工件类型分域，不按内部学科编号**：外部用户不认识「01_视觉感知」的内部编号语义；按「视觉训练 / 机载软件 / 飞控 / 仿真 / 地面工具 / 操作」分域，目录名英文（代码友好）+ 内容中文。
2. **文档一个家**：全部设计文档、说明书、日志、教训集中 `docs/`，按受众分层（getting_started → design → manuals → lessons → journal）；工程目录只放工程件 + 薄 README。
3. **教训是一等公民**：CUADC 社区传统 + 本项目最大特色。`docs/lessons/` 收三件：原《11_错误与经验总结》（全库错误总编）+ 本次新撰《错误与教训实录》《经验与方法总结》（从 164 个 AI 协作会话、495KB 工作日志、165 条 git 提交中挖掘）。
4. **诚实的过程开源**：工作日志总编、SSOT 全文（含执行计划）原样开源——「我们如何备赛」和「备赛结果」同等有价值（哈工大 `日志.md` 同思路）。
5. **git 白名单即开源边界**：`.gitignore` 白名单（自研文本资产）天然就是开源内容边界；大体量数据、权重、BIN 日志、第三方版权件一律不进开源树，仅在 THIRD_PARTY_NOTICES 说明获取方式。
6. **可复现性优先**：参数快照+台账、固件 SHA256 清单、数据集版本台账、模型 SHA 台账全部保留——这是西安石油 CI 实践与本项目既有制度的共识。
7. **脱敏后才出门**：内网 IP、私有仓库地址替换为占位符；AI 工具痕迹（.zcode/.workbuddy）、编译残留（pyc/exe/pdb/build_test）一律不进。

### 4.2 不进开源树的内容及替代说明（见 THIRD_PARTY_NOTICES.md）

- **第三方版权（红线）**：`08_参考资料/` 整目录（手册转写、大赛附件、NVIDIA/Ubuntu 安装包、四队仓库拷贝）、Gazebo models 比赛贴图、厂商 PDF；

- **大体量数据**：数据集/训练产物/rosbag/视频/dataflash BIN（白名单本就隔离）；
- **自研固件**：`.apj` 为 ArduPilot GPL 构建产物，随仓分发但注明来源与对应源码版本。

### 4.3 发布前必做检查（ checklist）

1. `grep -rn "sk-\|password\|密码\|api_key\|token" --include="*.*"` 复扫（已做初扫：无密钥）；
2. 内网 IP 复扫 `10\.\d+\.\d+\.\d+` 与 `192\.168\.`（已替换 3 处已知，需复扫确认无漏）；
3. LICENSE 年份与持有者名确认（当前占位「CUADC2026 多旋翼侦察与救援团队」）；
4. 决定仓库公开名（建议 `CUADC2026-multirotor-rescue` 或中文名）——10-18 已定名公开发布；同日晚开源树并入主仓并解并去重、独立仓删除退役（现状见完整映射表头部状态注）；

## 五、发布操作指南

```bash
cd 10_开源发布/CUADC2026开源仓库
git init -b main
git add -A
git commit -m "CUADC 2026 多旋翼侦察与救援 备赛全流程开源（首发）"
git remote add origin <新公开仓库地址>
git push -u origin main
```

- **License 选择**：代码 MIT（最大复用度，与 ROS 2 生态惯例一致；若担心被闭源参赛队直接商用可改 Apache-2.0 增加专利条款）；文档 CC BY 4.0（允许转载署名）。二者在 THIRD_PARTY_NOTICES 中声明边界。
- **平台**：GitHub（国际可见、哈工大/西安石油同在）为主，可选同步 Gitee（国内访问快）。
- **建议 pin**：发布时在本仓 `docs/README.md` 顶部回填实际仓库地址（替换 `<开源后填入实际仓库地址>` 占位符）。

## 六、赛后原仓重构方案（可选，未执行）

本方案**不改动现有工作仓**（备赛期 Jetson 同步路径、ops.py 入口、肌肉记忆都不能动），开源树是独立副本。若赛后希望原仓直接变成开源形态：

1. 按本报告 §三 映射表执行 `git mv`（保留 rename 历史）；
2. 同步更新根 README 目录总览 + SSOT §0 文档地图 + 各模块 README（AGENTS.md 硬规则 5 的双同步）；
3. 根 `.gitignore` 增加 08/09/99/10 等目录的显式排除声明（现已默认忽略）；
4. 工作日志总编中 `07_工作日志/` 等旧路径表述统一勘正（或保留并注明历史口径）；
5. 洗历史：`git clone` 出全新历史重推（现 `.git/lost-found/` 有 6.2GB 孤儿对象，且历史含大数据提交记录，不宜直接公开历史）。
